# 05 · 分阶段交付计划与验收矩阵

> 原则：**不做"只有界面 + 模拟数据 + 安装按钮"的演示版**。第一个可交付版本（P1）就必须是"能真转发、真出日志、网页能真查到"的垂直切片。
> 规模用 S/M/L 表示相对工作量级，不给编造的人日数字。

---

## 1. 阶段划分

### P0 · 基线与环境（S）
| 项 | 内容 |
|---|---|
| 交付物 | 本目录 6 份设计文档；`deploy/systemd/*`、`deploy/haproxy/*` 骨架；`scripts/verify-log-fields.sh`；`scripts/gen-third-party-licenses.sh` |
| 验收 | 在一台干净的 Ubuntu 24.04 节点上，按文档能装出 haproxy 2.8 + 三个服务单元，`systemctl status` 全绿；功能探针输出 `NodeCapabilities` |
| 阻塞风险 | 无 |

### P1 · 端到端垂直切片（M）— **第一个可交付**
打通一条真实链路，**不追求功能全，但每一环都必须是真的**：

```
新增业务(SNI) → 渲染配置 → 校验 → 推送 staging → haproxy -c → 原子发布 → 平滑 reload
      → 客户端真实连接 → HAProxy 写日志 → agent 收 → spool → 上报 → 分片落盘
      → 网页查询到这条记录 → 改规则 → 再发布 → 平滑生效 → 制造源站故障 → 页面显示真实错误
```

| 项 | 范围 |
|---|---|
| 含 | 业务/客户/节点/路由的 CRUD；渲染器（两种模式）；静态校验；helper 的 Validate/Publish/GetStatus；版本目录 + symlink 原子切换；平滑 reload；发布后端口自检；unix dgram 日志直投；agent 收包+spool+上报；mgr 摄入+解析+分片落盘；日志查询页（分页+时间范围）；审计表；前端骨架 + 登录鉴权 |
| 不含 | 指标采集、诊断规则引擎、DNS 调度、双节点切换、诊断包导出、压缩/配额（留 P3） |
| 验收 | 见 §2 矩阵中 P1 行，全部通过；且**用 `grep` 证明页面上的数据来自真实日志而不是占位数据**（比如把源站关掉，日志出现真实错误串，页面同步出现） |
| 关键风险 | HAProxy 日志字段可用性（→ 用 §04 的探针与字段验证工具提前消解） |

### P2 · 发布可靠性（M）
| 项 | 内容 |
|---|---|
| 交付物 | 发布锁（含看门狗超时）；版本历史与一键回滚；`publish_records` 全阶段记账；期望版本 vs 实际版本漂移展示；发布失败自动回滚 + 回滚后自检；多节点并行发布与逐节点结果 |
| 验收 | 矩阵 §2 的"发布"组全部通过，特别是：**语法错误/端口冲突的候选配置不会影响现有服务**；**发布中途 kill 掉 mgr 进程，节点仍用最后有效配置继续转发**；**回滚可验证** |
| 关键风险 | 原子切换的正确性（symlink + fsync）；并发发布（用锁 + 唯一索引机械保证） |

### P3 · 日志、指标与诊断完整化（L）— **重点阶段**
| 项 | 内容 |
|---|---|
| 交付物 | stats socket 指标采集（含 reload 纪元处理）；系统指标（CPU/内存/磁盘/网卡）；**实时在线连接**（不依赖结束日志）；分片轮转/压缩/配额/保留期，全部可在界面改；丢日志事件（4 类）与页面告警；诊断规则引擎（§03 §7.1 全部分类）；诊断四段式展示；脱敏诊断包导出 |
| 验收 | 矩阵 §2 的"日志/指标/诊断"组全部通过；**明确验证：未结束的长连接能在实时指标里体现**；**验证配额真的会触发且不阻塞转发**；**验证诊断包里没有密钥/其他客户数据** |
| 关键风险 | 大数据量下的查询性能（→ 分片 + 分页 + keyset + 压缩） |

### P4 · 管理安全（M）
| 项 | 内容 |
|---|---|
| 交付物 | 私有 CA + 一次性注册令牌（原子消费、可撤销、可轮换）；agent 双向 mTLS；证书自动续期与吊销；helper 白名单的完整边界测试；管理入口来源限制；密码 argon2id；会话与 CSRF；审计覆盖全部敏感动作 |
| 验收 | 用过期/已用/已撤销令牌注册均失败；用被吊销证书连接被拒；**helper 越权测试**（路径穿越、symlink、非法 version、非白名单 op）全部被拒；`grep` 代码库确认不存在 `sh -c`/`pkill`/字符串拼命令 |
| 关键风险 | helper 的边界正确性（用表驱动测试逐个攻击面覆盖） |

### P5 · 双节点高可用与阿里云 DNS 调度（L）
| 项 | 内容 |
|---|---|
| 交付物 | 业务与主/备节点绑定；两节点配置同步发布与一致性校验；DNS 适配层（阿里云普通解析 读写 + 手动改）；GTM 可行性评估报告；单控制者租约；健康判定引擎（阈值/观察/冷却/防抖）；切换日志与界面；DNS 漂移检测；A/AAAA/CNAME 接入关系检查 |
| 验收 | 矩阵 §3 双节点组全部通过 |
| 明确声明 | **DNS 高可用不是既有连接迁移，不保证零中断**（写进界面与交付文档） |

### P6 · 验收、加固与交付（M）
| 项 | 内容 |
|---|---|
| 交付物 | 全矩阵验收报告（含原始命令输出回填）；第三方许可清单；部署手册（含回滚手册）；运维手册（日常巡检、扩容、节点下线）；性能压测报告（连接数/吞吐/日志落盘速率上限）；限制与不承诺事项清单 |
| 验收 | 客户可照手册独立部署一套新环境 |

## 2. 验收矩阵（需求 §十一）

> 状态列：⬜ 未开始 / 🟡 进行中 / ✅ 已通过（附证据） / ⛔ 阻塞
> **证据列必须填可复核的东西**（命令 + 输出摘要 + 文件路径），不接受只写 "pass"。

| # | 验收项 | 验证方法 | 阶段 | 状态 | 证据 |
|---|---|---|---|---|---|
| 1 | 多域名共享 443，路由准确且互不串流 | 给 3 个域名各接一个**回显内容不同**的源站；分别连 3 个域名，断言收到的 banner 与域名一一对应；再交叉断言（连 a 绝不能收到 b 的内容） | P1 | ⬜ | |
| 2 | 无 SNI 的连接可以走指定 TCP 专用端口 | 用 `nc` 连 TCP 专用端口，断言不通 TLS 也能建立并回显；同时断言该端口不是 443 | P1 | ⬜ | |
| 3 | 未知 SNI 被拒绝，并可定位原因 | 连 `unknown.example.com`，断言被拒；页面诊断显示 `SNI_UNMATCHED` + 原始日志行 + 该 SNI 字符串 | P1/P3 | ⬜ | |
| 4 | 错误配置和端口冲突不破坏现有服务 | 故意提交端口冲突/语法错误配置，断言：发布被拒、现有 listener 未变、`show stat` 与之前一致、错误原因可见 | P2 | ⬜ | |
| 5 | 平滑更新时现有长连接持续工作 | 开一条长连接并持续收数据；期间发布新规则；断言长连接**不断**、数据不丢；断言新旧 `ver` 都出现在日志里 | P2 | ⬜ | |
| 6 | 发布失败恢复旧版本 | 在 verify 阶段人为注入失败（例如临时把 expected_listeners 改错）；断言自动回滚、旧版本生效、回滚后自检通过、记录里 `rollback_performed=1` | P2 | ⬜ | |
| 7 | 平台离线不影响转发 | 停掉 `relay-mgrd` 与 `relay-agentd`；断言转发照常；重启 agent 后日志补传 | P2/P3 | ⬜ | |
| 8 | 节点重启后恢复最后有效配置 | 直接 `reboot` 节点；断言 haproxy 起来就用 `current` 指向的版本，转发可用，不需要管理面介入 | P2 | ⬜ | |
| 9 | 模拟源站不可达，页面显示真实错误及对应日志 | 关源站；断言页面显示 `ORIGIN_CONNECT_FAILED` + HAProxy 原始错误串；断言发布验证**没有**因此回滚（区分"发布失败"与"源站不可用"） | P1/P3 | ⬜ | |
| 10 | 未结束的长连接能在实时指标中体现 | 建 10 条长连接保持不断；断言页面"当前连接数"约为 10（来自 stats `scur`），且这 10 条在连接日志里**还不存在** | P3 | ⬜ | |
| 11 | 日志轮转、磁盘配额和清理确实生效 | 改小配额到 1MiB 并灌流量；断言出现 `disk_quota` 事件、最旧分片被删、转发不受影响、页面有告警；改保留期到 1 天，断言超期分片被删 | P3 | ⬜ | |
| 12 | 诊断包不泄露凭据或无关客户数据 | 导出 zip 后逐个文件 `grep -Ei 'password\|secret\|token\|private\|BEGIN .*PRIVATE'`；再断言不含其他客户的 business_id | P3 | ⬜ | |

## 3. 双节点与 DNS 验收矩阵（需求 §十二.7）

| # | 验收项 | 验证方法 | 阶段 | 状态 | 证据 |
|---|---|---|---|---|---|
| H1 | A 的 HAProxy 停止，B 可用时按策略切换 | `systemctl stop shengyu-edgelink-haproxy` on A；断言达到失败阈值后触发切换、DNS 记录变更、切换记录含探测证据 | P5 | ⬜ | |
| H2 | A 整机不可达，自动调度仍能执行 | 断电/断网 A；断言 mgr 侧探测失败、调度器仍能操作 DNS（调度器不依赖任何转发节点存活） | P5 | ⬜ | |
| H3 | 单个探测点异常不会造成反复切换 | 只让**一个**探测点失败（其余正常）；断言不切换；再观察 10 分钟断言零切换事件 | P5 | ⬜ | |
| H4 | B 配置缺失或业务不通时不盲目切入 | 把 B 的配置回滚到旧版本 / 让 B 到源站不通；断言拒绝切换并告警「备用路径不健康」 | P5 | ⬜ | |
| H5 | A/B 都不可用时告警并停止震荡切换 | 同时打挂 A/B；断言只告警、切换事件数为 0（不来回跳）、页面明确显示"两路径均失败" | P5 | ⬜ | |
| H6 | A 恢复后遵守自动回切开关及观察时间 | 分别测 `auto_failback=off`（不回切）与 `on`（满足恢复阈值 + 观察时间后才回切）；断言不早于观察时间 | P5 | ⬜ | |
| H7 | DNS API 超时、限流、拒绝时正确记录与重试 | 用 mock provider 注入超时/Throttling/Denied；断言**先重读实际状态再决定重试**、退避重试、`dns_change_log` 有 RequestId 与 Code | P5 | ⬜ | |
| H8 | 手工在阿里云修改记录后能检测配置漂移 | 控制台手工改记录值；断言平台下次 reconcile 发现 `last_seen_value` ≠ 期望值 → 停止覆盖 + 告警 + 生成 `DNS_DRIFT` | P5 | ⬜ | |
| H9 | 客户不同解析线路和其他业务记录保持正确 | 同一域名下造多条线路记录（default / cn_telecom / cn_unicom）+ 其他业务记录；切换后断言**只有目标记录被改**，其余逐字段（值、TTL、线路、类型）不变 | P5 | ⬜ | |
| H10 | 旧 DNS 缓存、长连接断开及客户端重连行为 | 记录切换前后 TTL；用 `dig +trace`/权威 NS 直查验证权威已更新；断言既有长连接**不受影响**（这是 DNS 切换的公开限制）；观察客户端重连时间与 TTL 的关系并如实记录 | P5 | ⬜ | |
| H11 | A/AAAA/CNAME 接入关系检查 | 造一个 A 指向 A 节点但 AAAA 指向 A 节点的域名；断言切换时**两者一起改**或被明确拒绝（不允许只改 IPv4） | P5 | ⬜ | |
| H12 | 同一时刻只有一个自动调度控制者 | 同时起两个 mgr 实例；断言只有一个能拿到租约，另一个显示"非控制者"且不修改 DNS | P5 | ⬜ | |

## 4. 界面清单（需求 §十）

| # | 页面 | 关键内容（数据必须真实） |
|---|---|---|
| 1 | 总览 | 节点在线/离线、各节点版本漂移、业务总数与启用数、当前连接总数与速率、最近发布、最近告警（含丢日志事件）、DNS 调度控制者与健康 |
| 2 | 客户与业务接入 | 客户列表；业务列表（可筛客户/节点/模式/状态）；业务详情（含在两节点的路由与版本）；**新增业务向导** |
| 3 | 节点管理 | 节点信息（agent 版本、haproxy 版本、能力矩阵、公网 IP）、实时指标、配置版本与漂移、注册令牌管理、开启/停用 |
| 4 | 日志与诊断 | 多条件筛选（客户/域名/节点/业务 ID/客户端 IP/时间范围/异常类型）；连接日志表；筛选异常后展开**四段式**诊断卡；诊断包导出 |
| 5 | 配置版本及操作审计 | 版本历史（含 diff）、一键回滚、发布记录（分阶段结果 + verify 明细）、审计日志 |
| 6 | 业务组与 DNS 调度 | 业务组配置（首选节点/自动切换/自动回切/阈值/冷却）、受管 DNS 记录（含线路与 TTL）、当前 DNS 指向与两条路径健康、切换历史、手工切换（带前置检查） |

**新增业务向导流程（需求 §十）**

```
① 填写业务（客户/名称/备注/模式）
② 选择节点（主节点 + 可选备用节点，展示各节点能力矩阵与当前负载）
③ 填写源站（IP:端口；实时回显校验：非回环、非保留网段）
④ 自动检测（对该节点+该源站做 TCP/TLS 探测，显示真实结果；探测失败不阻止保存但强提示）
⑤ 发布（逐阶段进度：渲染→校验→推送→校验→切换→验证；失败给出原始错误）
⑥ DNS 接入说明（给出客户需要修改的 DNS 记录：类型/主机记录/记录值/TTL；并明确"如果要走平台自动调度，请把该记录交给平台接管"）
```

**界面硬约束**
- 不生成任何模拟监控数据；无数据时显示「暂无数据」而不是 0 或假曲线；
- 「连接数 / 请求数 / 流量」三个词在界面上有 tooltip 定义（见 docs/01 §1），TCP 模式下「请求数」显示「不适用（TCP 模式）」；
- 限制项在界面显著位置说明：不支持通配符域名、HTTP/3、ECH 真实域名识别、内网穿透；
- 不可用字段统一显示「不可用」；
- DNS 相关页面固定展示声明：**「DNS 高可用不迁移既有连接，不保证零中断」**。

## 5. 里程碑与依赖关系

```
P0 基线与环境
    └──▶ P1 端到端垂直切片 ★ 第一个可演示（但是真数据、真转发）
              ├──▶ P2 发布可靠性
              │        └──▶ P5 双节点 + DNS 调度
              └──▶ P3 日志/指标/诊断完整化
                       └──▶ P4 管理安全加固
                                 └──▶ P6 验收与交付
```

- 只有 **P1 完成**之后才允许对外演示——因为 P1 之后每一个数字都来自真实链路。
- P4 的安全加固可以并行做，但**上线前必须完成**：先用 P1–P3 在内部环境跑通，公网暴露前补齐 P4。
- P5 依赖 P2（需要可靠的两节点发布）与 P3（需要真实探测与日志证据）。

## 6. 明确的「不做 / 不承诺」清单（写进交付文档与界面）

| 不做 | 不承诺 |
|---|---|
| 客户私有化部署 | 永久不被封 |
| 软件授权与防破解 | 固定加速比例 |
| 计费、客户自助注册 | 零中断（尤其 DNS 切换） |
| 通配符域名规则 | 保证既有连接迁移 |
| HTTP/3、ECH 真实域名识别 | AWS/GCP 等等级的外部多地域探测（v1 用管理面 + 节点面探测点，如实标注来源） |
| 内网穿透 | 覆盖"东南亚用户端体验"（节点探测 ≠ 终端用户体验） |
| 客户获得服务器/配置/后台权限 | 平台探测结果代表真实用户请求 |
